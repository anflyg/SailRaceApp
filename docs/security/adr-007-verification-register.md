**Register status:** Living evidence index; not an architecture decision, security certification, or release approval.  
**Last updated:** 2026-10-31.  
**Scope:** Cloudflare R2 object creators/deleters, deployed Workers and Queues, privileges, delayed-write resurrection, recovery, and relevant D5/D6 evidence.

**Safety gate:** [ADR-007](../architecture/decisions/adr-007-deletion-resurrection-fencing.md) is **PROPOSED — NOT ACCEPTED**. Production race/account deletion is **not authorized or verified**. This register cannot change that status. No production object writes/deletes, Secret changes, or credential revocations are authorized by this document.

## How to maintain this register

- Use stable control IDs. Update only entries affected by a code/configuration/permission change, newly obtained evidence, or an explicit verification-expiry event. Do not repeat unrelated checks just because work moves to another chat or branch.
- For changes in **SailRaceApp**, update affected entries in the same PR. For changes in **tackwise-api**, **tackwise-contracts**, or **TackWiseAnalysis**, create a linked **SailRaceApp documentation PR** that updates affected IDs, or track missing evidence explicitly until verified; a PR in another repository cannot modify this register. Coordinate the evidence update before calling the relevant change fully verified. For changes made directly in Cloudflare, record an operator-reviewed follow-up with the observation date and affected deployed environment.
- Mark **VERIFIED** only for the *narrow claim and evidence surface stated in that row*; it is not proof of overall production safety. **PARTIAL** means some evidence exists but an acceptance criterion is missing. **OPEN** means the required evidence has not been established.
- Evidence types: **SOURCE** = inspected repository code/ADR; **CI** = GitHub Actions/build; **OPERATOR** = dashboard screenshot or operator-reported check; **PROVIDER-REPORTED** = operator-reported nonproduction R2 execution, not independently reproduced; **MODEL** = deterministic local tests. Never promote a MODEL or OPERATOR observation to provider-internal concurrency proof.
- Record dated evidence references and an event-based recheck trigger. A current deployment screenshot is a point-in-time observation, not a guarantee after future rollouts or rollbacks.
- **Public-repository data minimization:** Do not commit credential values, hidden Secret identifiers, account IDs, actual race/user UUIDs, raw R2 keys, GPS, provider response bodies, token names that expose operational inventory, or unredacted operational screenshots. Keep detailed credential-to-service mapping and journals in access-controlled evidence with an approved retention policy; summarize outcomes here without secrets.
- If a source or test contradicts earlier evidence, retain the history, mark the control PARTIAL/OPEN, and link the corrective review. Security, CRA, GDPR, architecture, retention, or permission-design changes must be flagged before implementation and documented in the appropriate authoritative repository.
