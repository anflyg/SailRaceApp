# Security Incident Response

**Status:** Initial stub.

## Basic flow

1. Detect or receive a security incident/suspected vulnerability.
2. Contain immediate exposure where possible.
3. Preserve relevant evidence without unnecessary personal-data collection.
4. Assess affected users, data, versions and exploitability.
5. Determine whether CRA, GDPR or other notification/reporting obligations are triggered.
6. Remediate and release fixes.
7. Notify affected users/regulators where required.
8. Record lessons learned and update risk/threat documentation.

CRA and GDPR notification timelines must be checked against current law/guidance at the time of an incident. Do not rely on this stub as legal advice.
