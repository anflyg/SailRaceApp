# C3: Proposed minimized race-performance history and lifecycle

**Status: PROPOSED, 2026-11-26.** Review artifact for [D1–D11](../product/race-performance-change-decisions.md), especially D6/D11; [ADR-010](decisions/adr-010-vmg-wind-reference-lifecycle.md) and [ADR-012](decisions/adr-012-wind-history-and-maneuver-analysis.md) remain PROPOSED. No collection, contract, implementation, migration, release, or G1/G3 approval follows. C1 is the working lifecycle proposal, not an accepted ADR. G3 must review this entire model, including retention and feasible limits; G1 must resolve late-origin binding, snapshot compatibility, ordering, corruption fallback and local ownership before implementation.

## Purpose and scope

Enable an owner to understand which approved wind and eligibility underpinned each recorded VMG and the approximate evolution of the displayed tactical marker; support comparable accepted tack references without storing continuous HDG or motion. Treat all of this as personal race data, even without coordinates. Keep W0, Wvmg and Wtactical separate. Preserve the existing gun snapshot and all existing GPS recording decisions; this proposal adds no GPS cadence, native motion stream, roll/pitch, debug matrix, tracking, live telemetry, analytics, owner identifier or cloud dependency to race operation. A bounded sampled tactical series cannot reconstruct motion between observations or assert true wind; validate its usefulness before collecting it.

## Candidate raw format and exact field inventory

The proposed wire identity is `rawFormatVersion: 2` (a candidate reserved for C4, not an existing supported format). Root race identity, recording/gun/end times, course snapshot, position samples and permitted legacy race events retain their raw-v1 meanings; do not reinterpret or overwrite the original gun snapshot. The following fields are **required unless explicitly nullable**, strict objects reject unknown properties, and integers are JSON safe integers. `null` is explicit absence, not zero or a request to fall back to Course wind. Use UTC RFC 3339 timestamps with exactly millisecond precision (`YYYY-MM-DDTHH:mm:ss.sssZ`), validated calendar dates; angles are finite degrees normalized to `[0,360)`, speed is knots, durations are milliseconds. All times and ordering must be representable without rounding across an effective boundary; if not, mark the affected observation unavailable and preserve the original race. C4 must verify the precision against actual native clocks and reject, rather than silently round, any loss of ordering.

| Object / field | Proposed type, units and meaning |
| --- | --- |
| `historyVersion` | Integer `1`, independent of `rawFormatVersion` and `analysisVersion`; unsupported values fail closed. |
| `origin` | Exactly one object or `null`; null means no approved race-bound W0 by end. An origin is bound once for the race, independent of later Course edits. |
| `origin.kind` | `gun-snapshot` or `post-gun-first`. The latter is allowed only when no usable W0 was bound by gun and the first approved later measurement belongs to the same race. |
| `origin.headingDegrees` | W0 wind-FROM true-north direction, degrees `[0,360)`. It is never a derived Wvmg or a mutable Course field. |
| `origin.capturedAt`, `origin.effectiveAt`, `origin.order` | UTC ms capture completion, approval/binding effective time and global publication order. Capture precedes or equals effective time. For `gun-snapshot`, use the actual approval/binding instant at or before the gun; for late W0, use the actual approval/committed binding instant after the gun, **not** capture start or gun time. Source-time basis and trustworthy capture/approval time remain G1 review points. A late W0 cannot affect any sample whose source timestamp predates `effectiveAt`, even if it arrives later. |
| `origin.quality` | Strict `{model: "core-motion-v1", referenceFrame: "true-north", quality: "good", sampleCount: integer 12..10000, spreadDegrees: finite 0..10}`. Validate heading and evidence against the existing usable-wind gate; this is a minimized assertion, not proof of accuracy or a native debug dump. The sample-count ceiling is a proposed safety limit, not a new sensor-quality threshold. |
| `references` | Array 0..2048 accepted stable-tack records, ordered by acceptance sequence. No rejected-window or per-motion records. |
| `references[].sequence`, `effectiveAt`, `order` | Sequence starts at 1 and increases exactly by 1; effective time is the fresh completing HDG sample timestamp from C1, strictly increasing across acceptances; `order` is global committed publication order. `effectiveAt` must be at or after W0 effectiveness and the gun. Duplicate replay of identical accepted record is idempotent; conflicting sequence/order, non-finite, stale, out-of-order or unsupported evidence fails closed. |
| `references[].tack`, `meanHeadingDegrees`, `alphaDegrees`, `windDegrees` | `starboard` or `port`; locked true-north circular mean and derived Wvmg in `[0,360)`; manually configured full alpha integer 70..110°. Wind must equal normalized mean + alpha/2 on starboard or mean − alpha/2 on port, within a proposed 0.000001° serialization tolerance. Accept only one alpha epoch throughout the window; keep previously accepted Wvmg frozen. |
| `references[].quality` | Strict `{sampleCount: integer 5..10000, spreadDegrees: finite 0..10, expectedDeviationDegrees: finite 0..15, referenceFrame: "true-north", gateVersion: "stable-tack-v1"}`. Values summarize the actual accepted window and existing gates, not raw samples or confidence in physical accuracy. A version change or evidence not available is not fabricated. |
| Each GPS `samples[]` record: `order`, `vmg` | Add global `order` and required `vmg: {reference, eligibility}`. `reference` is `null`, `{kind:"origin"}` or `{kind:"accepted", sequence:1..2048}`. It identifies the reference actually used/retained at that sample's processing; no copied wind or computed VMG value. `eligibility` is exactly `eligible`, `no-origin`, `origin-mismatch`, `gps-unavailable`, `gps-stale`, `speed-below-threshold`, or `ordering-unavailable`; C4 must map existing gates to these categories and define precedence deterministically. Eligibility is the app's decision at sample processing, not an assertion that quality can be independently reconstructed from v1 fields. An eligible sample requires a valid reference, usable origin and existing GPS SOG/COG/speed gates. A noneligible sample may retain a compatible reference for provenance, but must never produce VMG. `no-origin` requires null reference. |
| `tactical` | Array 0..50000 strict `{sampleIndex, status, headingDegrees}`. `sampleIndex` is zero-based into the final source-time-sorted samples array; indices strictly increase, unique, within bounds. `status` is `available` or `unavailable`; heading is the last displayed tactical estimate `[0,360)` when available and `null` otherwise. No coordinates or duplicate timestamps; sample index supplies time and ordering. It is separate from Wvmg and the original W0 scale. |

`origin` and each accepted reference are one record per race event, not separate histories for calibration and tack feedback. `order` is a race-scoped positive integer 1..1000000, unique across origin, accepted references and GPS sample processing events. Gaps are allowed in this global order (events may be unrecorded); acceptance *sequence* is contiguous. No timestamp or sequence proves authorization, native accuracy, independent wind evidence or that an alpha setting remained unchanged throughout a window; the aggregate evidence is a client assertion requiring trusted local epoch tracking and G1 review. No local owner context, tokens, names, email, object keys, debug data or device identifiers belong in the raw artifact.

### Cadence, coverage and bounded failure

At the existing recording schedule only, associate the last displayed tactical value/availability with the first recorded GPS sample at least 5 seconds of **GPS source time** after the preceding tactical observation, starting with the first recorded sample; if a late-arriving source timestamp is not at least five seconds after the most recently captured tactical observation, omit that tactical observation rather than backfill it; never increase GPS recording rate or emit an extra sample to meet cadence. If unavailable at that point record `unavailable`, not a stale value as current. Record the observation only if the displayed value can be related to that sample without look-ahead; otherwise record unavailable. This observes at most once per five source seconds (including when existing start recording is faster), so at most 720 observations/hour and 50,000 overall. The last observed value is a discrete observation, **not** permission to interpolate across gaps, infer transition times, or reproduce every displayed shift. Existing per-sample VMG eligibility is captured for each existing GPS sample; transient changes between samples are not claimed. A D6 adequacy decision requires synthetic and native/on-water review; if this cadence cannot explain meaningful shifts, mark that coverage insufficient and seek a separate reviewed choice rather than silently increasing collection.

Provisional raw-v2 ceilings: 50,000 GPS samples (at least one), 2,048 references, 50,000 tactical observations, 10,000 existing legacy events, 5,242,880 compressed bytes and 20,971,520 expanded bytes. The latter three and sample ceiling match current [raw-v1 upload limits](https://github.com/anflyg/tackwise-contracts/blob/main/docs/race-upload-v1.md#provisional-limits); they are **proposed for v2**, not evidence these richer objects fit or existing server support. No new free text. Validate all counts, serialized/expanded/compressed sizes, time bounds, finite numbers, references and semantic rules before upload; measure near-limit memory, CPU and worst-case canonical bytes. If a limit, atomic write or complete history cannot be maintained, keep race-critical operation offline and preserve the original local race; explicitly mark the new history incomplete and make v2 export/sync unavailable until a separately reviewed recovery path exists. Never silently truncate, synthesize an eligible value, regenerate prepared bytes, or pretend D6 is satisfied. A narrower local-only export of the existing race may remain available under the existing format with clear completeness metadata; details need G3 review.

## Ordering, D11 and atomic recovery

Only a committed origin/reference published before a sample's processing (`event.order < sample.order`) is eligible for that sample, and only if its `effectiveAt` is **at or before the GPS source timestamp**. Select the published candidate with greatest effective source time, with global order breaking equal-time ties; an origin at equal timestamp applies only after its publication. Persist the sample's selected reference and eligibility, and validate them against these rules rather than recomputing from the latest reference at export. A late-arriving GPS sample uses its own source time and the publications that had already occurred when it was processed; no future-effective reference or later processing-time calibration may leak backward. Sort serialized samples by `(source timestamp, order)`, retaining `order` and remapping tactical indices; do not rewrite an already emitted decision. Preserve the original ordering provenance; an unresolvable clock discontinuity or ambiguous tie withholds the affected VMG and cancels pending acquisition. The event order is not a replacement for actual timestamps. For D11, pre-origin samples remain `no-origin` even if processed after origin commit; at equal time publication order decides. If no reliable approval/effective instant can be established, withhold rather than guess.

The local checkpoint is a **separate** local format `checkpointVersion: 1`: one atomic, integrity-checked generation holds the local race UUID, a local ownership-context binding, immutable gun snapshot identity and complete committed origin/reference history, current effective reference, global order high-water mark, derivation/history versions, completeness marker and the sample/history commit cursor. It contains no auth token or credentials and is never a cloud ownership assertion. A transaction, or durably written generation with atomic commit pointer, must make an acceptance/origin and its matching history/checkpoint visible together, before any dependent sample or live display observes it. Sample decisions and cursor must commit consistently with that generation; retry of an identical commit is idempotent, conflicting duplicate or regressing order fails closed. Checkpointing must not serialize pending acquisition windows; background/restart discards them and Continue reacquires fresh sensors. A failed durable commit leaves the previous generation authoritative. At crash recovery, validate version, integrity, race UUID, owner context, snapshot and origin, counts, cursor, reference chain and order before publishing; recover complete old or complete new generation, never a mixture. Atomicity/OS durability and crash injection need native evidence, not assumed filesystem guarantees.

For invalid/missing/incompatible generations, preserve the original race, withhold derived recovery and use only that race's separately and reliably persisted committed W0 if G1 approves this fallback; never infer a late W0 from current Course or a partial generation. No samples before explicit Continue. On account switch/sign-out clear runtime references and pending work; never bind local data to a new account by implication. A proposed distinct unsigned local-only context is not a cloud owner identity; local ownership, reauthentication and adoption policy remain open under G1/G3.

## Data lifecycle and contract review

| Stage | Proposed treatment and approval required |
| --- | --- |
| Local recording / recovery | Store only in app-private race-scoped storage, protected by an approved iOS file-protection class; exclude from system/device backups by default **if product confirms that choice**, otherwise define encrypted backup, access and deletion/restore rules. Local race UUID and owner context are opaque and not names/email. Keep checkpoints only while recovery is useful; remove temporary/obsolete generations safely after commit and on race deletion. Exact class, backup choice, storage limits and retention are open. |
| User export | A portable, versioned owner-initiated race export contains approved history, completeness and explicit unavailable states together with race data; no tokens or internal storage keys. Include late W0 separately from unchanged gun snapshot. An exported copy leaves app control; explain that deleting the app's race cannot recall it. Existing exports retain their existing semantics. |
| Cloud sync | Only explicit authorized per-race sync after completion; construct a single new-version raw artifact after approved contracts and capability negotiation. Use server-issued opaque cloud race UUID, authenticated per-user ownership and entitlement, existing private conditional immutable upload/verification and exact prepared gzip/digest retry rules. Preserve every already prepared/accepted v1 artifact and digest; do not upgrade or mutate it. Unsupported version fails closed and leaves local race intact; do not silently fall back to v1 or add a sidecar. Reader, upload capability, version and result support must precede enabling a writer. |
| Retention and deletion | Proposed same user-owned race lifetime for history as its race, with no independently indefinite history retention; exact local/cloud periods, backup retention, legal exceptions and export handling need explicit approval. Individual race and account deletion must cover local checkpoint/generations, local history, unsynced/prepared artifacts, cloud accepted/pending raw objects, metadata and all derived versions. Preserve references for retryable cross-store deletion and prevent stale uploads/jobs/restores from resurrecting data. Offline local-only and cloud deletion must be visibly distinguished; deleting cloud account must not claim remote access to an offline device. |
| Backup / restore | Inventory device and provider backups, schedules, encryption/access, deletion propagation, maximum persistence and restore reconciliation before enablement. A restore must respect current account/race deletion gates and never resurrect deleted cloud data; do not claim provider backup behavior is solved. |

Raw-v1 keeps its strict schema and historical analysis semantics, including backend fallback from missing sample wind to Course wind. V2 must **not** use that fallback for an explicit unavailable VMG sample or before late W0. In this proposal v2 omits raw-v1's optional per-sample `windDirectionDegrees`; `vmg.reference` is the sole wind-VMG lineage. Existing `course.windDirectionDegrees` remains the original gun-time course field and may be absent even when late W0 exists. C4 must define v2 independently and test that no v1 reader accepts v2 as v1. No new schema or endpoint is authorized here. New raw/history version, `analysisVersion`, result and owner-projection versions evolve independently; legacy accepted gzip/digest, immutable objects and historical results never change, and no automatic backfill/reanalysis is implied.

## Proposed G3 privacy, security, CRA and contract review record

These are **draft amendments for review**, not completed compliance evidence or approval:

- **Inventory / processing:** add origin/quality, accepted mean/tack/alpha/times, sparse tactical observations, sample eligibility/reference and local checkpoint/ownership context to the race-data inventory. Purposes are race recovery, owner-requested analysis/export/sync and lineage; prohibit product analytics, advertising, tracking and unrelated reuse. Record controller, processor/subprocessor, transfers, access, recipients, lawful basis/consent assessment, privacy notice and data-subject export/deletion procedures. These derived observations and opaque IDs remain personal data and may reveal location or behavior.
- **Retention / backups:** approve local, temporary, accepted/pending cloud, result and backup periods and deletion exceptions; test local/cloud export and deletion, account change, backup restore and non-resurrection. Existing 30-day account target and pending-upload cleanup targets are not evidence that this new lifecycle is implemented or complete. Unresolved retention/deletion blocks collection.
- **Threat / CRA:** assess forged or replayed origins, cross-race/account reference substitution, later Course mismatch, stale order, partial checkpoint rollback, corrupt/oversized/decompression bombs, malformed reference chains, unsupported versions, unbounded analysis, untrusted client quality claims, private object disclosure, stale account responses and delayed deletion/sync. Mitigate with strict bounded parsers, authenticated owner/entitlement checks (including service-role operations), validated race identity and times, atomic commits, private R2, no credentials on clients and no payload/location/secrets in logs. Origin quality is client-provided evidence, not cryptographic sensor attestation. Model offline failure, abuse and resource ceilings in the CRA risk register and record synthetic/native tests, dependency, recovery and vulnerability-management evidence before release; no CRA/GDPR compliance conclusion is implied.
- **Existing security evidence:** consult [ADR-007 verification register](../security/adr-007-verification-register.md); `TW-D5-017`–`TW-D5-022` deletion/fencing/retention/restore gaps remain open. Assess affected controls when contract, object lifecycle, permissions or restore behavior changes; do not repeat unaffected provider checks or mark them verified. No cloud deletion or provider action is authorized by this proposal.
- **Contracts / approval:** architecture, product for visible fallback and adequacy, contracts, security/privacy, GDPR/CRA and release owners must review exact fields, bounds, use, retention, backup and cross-store deletion. C4 must create strict valid/invalid golden fixtures for old/new versions, D11, ties, unavailable states, overflow and atomic-failure recovery, and demonstrate reader/writer compatibility and resource bounds. G1 must approve the origin and account lifecycle first. No analysis confidence policy or G4 approval is implied.
