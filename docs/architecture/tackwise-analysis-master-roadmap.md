# TackWise Analysis master roadmap

**Status:** Delivery roadmap; architecture decisions remain in the linked ADRs.

**Last reviewed:** 2026-10-25

## Product outcome

A sailor completes a real race with TackWise Race on iPhone, synchronizes it securely after racing, and views a useful analysis at [analysis.tackwise.se](https://analysis.tackwise.se). Recording must remain available offline. Raw race data stays private, and every cloud operation must enforce authenticated ownership.

This is the single cross-repository delivery roadmap. It tracks outcomes and release gates; it does not replace or copy detailed designs. The [race upload implementation roadmap](race-upload-implementation-roadmap.md) remains the detailed plan for upload, analysis dispatch, API handoff and deletion work. Product behavior is described in [TackWise Analysis](../product/tackwise-analysis.md). The architecture constraints are in [ADR-003](decisions/adr-003-first-race-upload-and-sync.md), [ADR-004](decisions/adr-004-analysis-dispatch-lifecycle-and-cleanup.md), [ADR-005](decisions/adr-005-analysis-result-v1-identity-and-storage.md), [ADR-006](decisions/adr-006-cross-store-race-and-account-deletion.md), and [proposed ADR-007](decisions/adr-007-deletion-resurrection-fencing.md). ADR-007 remains **PROPOSED** and is not accepted by this roadmap.

## Sequencing and release boundaries

M1 is the security and identity gate for real synchronization. M2 precedes processing real uploaded races; M3 precedes the result-dependent parts of M4 and M5. M5 may develop against synthetic fixtures while M1–M4 proceed, but synthetic UI work does not authorize access to real race data. M6 demonstrates the integrated path in a controlled non-production environment. M7 is a separate release gate: an end-to-end demonstration does not authorize deletion or beta access.

No accounts currently exist, so there is no planned account-gate backfill. Before any rollout that relies on this assumption, verify the deployed account base is empty using a reviewed, privacy-preserving check. PR #40’s preflight only reports local aggregate classifications; it does not authorize or perform a backfill.

Production migration application, production configuration changes, deployment, deletion activation, beta enrollment and acceptance of proposed architecture require separate explicit approval. A merged implementation PR alone authorizes none of those operational steps.

## Parallel product-design track — not a delivery gate

[Draft PR #18](https://github.com/anflyg/SailRaceApp/pull/18) proposes a separate `docs/product/analysis-comparison-and-coaching.md` for within-race lap/leg comparisons, personal race-to-race trends, reproducible/versioned deterministic coaching insights and optional provider-free/satellite/hybrid/future 3D map backgrounds. Its latest reviewed 243-line document compares dated Google/Mapbox pricing and leaves provider, shoreline data, metric comparability and GPS/location disclosure terms open. Future multi-sailor per-race/per-participant sharing is **unapproved** and requires a separately reviewed security/privacy architecture, consent/access, revocation, deletion and retention design. The proposed map controls must consider geographic disclosure through tile/viewports and automatic camera following even when no raw GPS polyline is submitted to a map provider. This design PR does not alter or unblock M1–M7, nor approve third-party map requests, re-analysis, data sharing or production data.

## Working model and approvals

ChatGPT and the product owner make architecture decisions. Codex implements explicitly approved tasks, runs relevant tests and documentation checks, and prepares Draft PRs for review. Keep manual effort small through focused changes, repeatable checks and clear acceptance evidence. The product owner reviews decisions and Draft PRs; no automated merge, production deployment or architecture change occurs without approval.

Security, privacy, GDPR and Cyber Resilience Act evidence is built alongside implementation, following the repository's [security baseline](../security/cra-risk-assessment.md), [threat model](../security/threat-model.md), [privacy design](../privacy/privacy-design.md) and [retention policy](../privacy/retention-policy.md). This roadmap makes no legal conformity claim and does not approve an unresolved design choice.
