# ADR-010: Separate accepted VMG wind from tactical wind

**Status: PROPOSED — not accepted or implemented.**  
**Date:** 2026-11-26.  
**Product authority:** PR #84 D1–D5; D3/D6 for downstream evidence.  
**Approvals needed:** G1 and relevant G3 in the [technical design](../race-performance-technical-design.md).

## Context

ADR-008 establishes native true-north W0 and transient filtered HDG. The existing tactical state machine accepts a locked mean after stable-tack acquisition, then continuously updates the tactical estimate during steering. Both live and logged wind VMG currently use initial Course wind. Copying the tactical estimate into VMG would violate D1/D2; replacing Course wind would violate W0 origin and locked post-gun snapshot semantics.

## Proposed decision

Keep three distinct values: immutable race origin W0, unchanged Wtactical, and race-scoped Wvmg. Initialize Wvmg only from usable W0. Expose a once-only reference-acceptance event from the existing tactical acceptance seam, carrying race/sequence, effective time, locked true-north mean, tack, alpha at acceptance and minimal quality evidence. Compute Wvmg from that mean plus alpha/2 on starboard or minus alpha/2 on port. Normal steering, failed acquisition and sensor loss do not replace accepted Wvmg.

Validate derived wind by its accepted origin/evidence chain, separately from the existing native capture equality gate. Reuse existing GPS freshness/reliability and speed guards for live VMG; retain the current tactical state machine/visual behavior. A reference acceptance must be idempotent and must never cross race/session boundaries. No new live controls, labels or telemetry are selected by this ADR.

Own state above tabs. Proposed recovery persists a minimal versioned local checkpoint atomically with the accepted-reference history after G3 review. Continue explicitly restores only a matching race/origin/derivation version and permitted local ownership context. Pending windows are discarded after restart/backgrounding, fresh HDG/GPS must be reacquired, and no samples are recorded before Continue. Tabs preserve runtime acquisition. New race clears the state; End stops updates. Missing/corrupt/incompatible checkpoints fall back to that race's valid W0 or unavailable, never another race's acceptance.

**Owner clarification C0 (2026-11-26):** the sailor alone sets and changes `Slagvinkel` (`alpha`) manually. TackWise may report an observed angle and a voluntary post-race suggestion, but must **never automatically change** the configured alpha. This confirms input ownership, not the lifecycle behavior of an alpha edit during a race.

**Owner-approved G1 behavior (2026-11-26):** every new angle-dependent calculation reads the currently configured alpha, including a manual edit made during a race. An already accepted Wvmg is **not** retroactively recalculated; it remains frozen until the next eligible accepted stable-tack reference, which uses the alpha configured at that acceptance. If alpha is changed during an in-progress sampling window, the technical design must ensure the new acceptance uses one consistent alpha epoch (e.g. restarting/revalidating the window), rather than mixing old and new settings; the exact transition remains engineering design. Post-gun Course mismatch must retain existing withholding rather than silently changing the race origin. The proposed transitions and ordering below resolve the engineering design for review; G1/G3 approval remains open. No G1 closure or ADR acceptance is implied.

## Proposed lifecycle matrix (C1; review required)

W0 is the usable Course capture and its matching native metadata, locked in the race snapshot at the gun. Before the gun, follow the existing prestart snapshot updates; Wvmg follows the currently usable prestart W0, or is unavailable. The existing logger locks the snapshot at the gun even if wind is missing; a later Course measurement does not update it. Therefore a missing or unusable gun snapshot withholds race-bound VMG; allowing late origin establishment would require separate approval. The tactical engine may still follow its existing post-gun Course behavior. The existing Course/race compatibility and quality gates continue to control availability. Wtactical and its W0 scale origin remain independent of Wvmg.

| Event | Proposed VMG reference and acquisition transition |
| --- | --- |
| Prestart / gun | No stable-tack acceptance before the recorded gun. At gun, bind to the race snapshot and initialize from its usable W0; if no usable compatible W0 exists, withhold. After gun and usable W0, seek the first eligible tack without requiring a maneuver. |
| Stable tack accepted | After existing 5-second confirmation and 0–20 s settling / 20–30 s sampling, apply existing quality, freshness, upwind, sample-count, spread and expected-sector gates. Atomically publish one acceptance with mean, tack and current consistent alpha; starboard adds alpha/2, port subtracts it, normalized to [0, 360). Freeze the result until another accepted reference. |
| Rejection / tack / downwind / HDG loss | Preserve the last accepted Wvmg (or W0 fallback); reject or cancel pending evidence and re-seek under existing tactical rules. Retention does not override GPS, origin compatibility or other availability gates. |
| Manual alpha edit | Every subsequent angle-dependent calculation reads the current setting. Do not recompute accepted Wvmg. An actual change invalidates the entire candidate and reference window, including settling and samples; begin a fresh 5-second candidate and 30-second establishment under the new alpha when eligible. This includes an edit at 20 s, during sampling or at acceptance. The existing tactical engine already resets on alpha change; retain that behavior and do not reset Wvmg with it. No acceptance may combine epochs; order an edit before a simultaneous acceptance, so the old window cannot accept. A no-op setting write does not reset. |
| Tab change | Preserve race-scoped state and in-flight acquisition; neither restart clocks nor duplicate acceptance. |
| Background / foreground | On background, invalidate in-flight candidate/window and checkpoint the last committed acceptance; never count background time or reuse its pending samples. On foreground reacquire fresh sensors and start a new candidate when eligible; keep accepted Wvmg subject to availability gates. Preserve existing native stream lifecycle. |
| Checkpoint / crash | Commit the acceptance record and matching checkpoint as one recoverable generation before exposing that acceptance to VMG or samples. A crash yields the complete prior or complete new generation, never a mixed pair. A failed write leaves the prior committed reference effective; retry idempotently or remain on that reference. No in-flight window is durable. |
| Restart / explicit Continue | Until Continue, do not record or advance acquisition. Validate the complete committed generation against race, locked W0 and metadata, derivation version and ownership context; restore its last acceptance only if all match. Discard pending windows and reacquire fresh HDG/GPS; never infer settling time across interruption. A changed current alpha does not alter the restored accepted value, but governs new acquisition. |
| Missing, corrupt, partial or incompatible state | Reject the entire derived generation, including its history; do not salvage an isolated Wvmg or splice generations. Use only the same race's usable, compatible W0 as fallback; otherwise withhold. Do not rewrite or damage the race snapshot. |
| Account change / sign-out | Cancel pending work and clear in-memory derived state immediately; never transfer an acceptance to another account. Restore only on explicit Continue with an exact authorized owner binding. For unsigned local races, propose a distinct local-only ownership context, never an automatic binding to a signed-in user; ambiguity withholds derived recovery pending owner policy. Existing race access/deletion rules remain in force. |
| Course wind mismatch | A post-gun Course heading or capture metadata inconsistent with the locked snapshot withholds wind-dependent VMG under the existing compatibility gate, cancels pending acquisition, and does not mutate W0 or the last acceptance. If the compatible snapshot is restored, the retained reference may be used again with fresh GPS; reacquire a new tack for further acceptance. An incompatible Course edit is not a new race or a replacement W0. |
| End / new race | End stops acquisition and updates. A new opaque race UUID starts with its own usable W0 or unavailable, empty acceptance sequence and no inherited window or reference, even for the same account or Course. |

### Atomicity and time ordering

The proposed durable unit is a versioned, integrity-checked generation containing race UUID, owner-context binding, immutable W0 identity and quality provenance, derivation version, ordered accepted-reference records and a checkpoint whose sequence and value match the last record (or W0 initialization). Use an atomic transaction or durable generation plus atomic commit pointer; validate the complete unit before publishing or restoring it. Specify storage, integrity, bounds, export, deletion, backup, retention and crash guarantees in G3 before collection. Never include credentials or raw sensor samples. Concurrent or delayed writes must not roll the committed sequence backwards; duplicate sequence/payload is idempotent, conflicting duplicates and gaps are rejected. This is a proposed architecture/security/privacy change, not authority to implement or collect.

Assign acceptance effective time to the timestamp of the fresh HDG sample that completes successful validation (at or after 30 s), not window start, wall-clock callback time or the mean's sample time. Require strictly increasing acceptance source timestamps within a race and a monotonic acceptance sequence; duplicate/out-of-order or invalid/future/stale source timestamps cannot advance acceptance. Use the current tactical timestamp guards; do not fabricate time after clock discontinuity: cancel the window and re-establish with valid ordered fresh samples. At processing time a sample uses the latest already-published acceptance whose effective source time is earlier than its GPS source timestamp; at equal timestamps it uses that acceptance only if its commit/publication precedes the sample's processing in a shared local event order. Otherwise it uses the preceding reference. Preserve this tie order in any separately approved history. A late GPS sample selects by its own source timestamp and recorded tie order, never a later reference. If ordering or compatible reference cannot be established, withhold rather than invent a value; do not rewrite already emitted samples retroactively. This ordering is a proposed requirement for future contract work, not permission to alter raw-v1 or record additional telemetry.

## Alternatives

- Continuous tactical estimate as Wvmg: rejected because steering would change the VMG reference.
- Require two tacks: rejected because D2 explicitly permits one; two tacks serve feedback only.
- Mutate W0/native measurement metadata: rejected because provenance, scale origin and historical interpretation would be corrupted.
- Runtime-only Wvmg with W0 fallback after restart: smaller implementation, but loses the accepted reference across recovery. Keep as an explicit owner-reviewed alternative if durable recovery cannot be qualified; do not silently choose it.

## Consequences and pending decisions

Local state persistence changes ADR-008's transient-only boundary for this new derived data; it needs architecture/security/privacy approval, not a silent amendment to ADR-008. The proposed crash, account and unsigned/local ownership policies above require G1/G3 owner review before implementation. Native streams, the three-second HDG filter, runtime R/S calibration and W0 capture quality model stay as established.

No cloud schema follows automatically. D6 history/lineage is separately proposed in [ADR-012](adr-012-wind-history-and-maneuver-analysis.md). No legal-compliance or release readiness is implied. Acceptance is the future evidence matrix D1/D2/D4/D5 in the design, including circular boundaries, reference replay, quality withholding and actual native/on-water validation.
